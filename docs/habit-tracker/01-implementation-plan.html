02 Planning parameters

  • Sprint length: 1 week. Each sprint ends with a working, on-device-verified increment — never "code complete but unverified".
  • Team: Nadeem (product decisions, device testing, accounts) + Claude Code (implementation, tests, docs). Claude does everything possible; Nadeem handles account-gated actions only.
  • Branching: one branch per sprint — habit-s<N>-<short-desc> (e.g. habit-s1-backend-models), merged to the active feature line at sprint close.
  • Feature flag: everything ships behind habits_enabled from Sprint 1 — the tab simply doesn't render when off. PoC testers get it turned on per-account.
  • Estimation: Fibonacci story points (1/2/3/5/8). A 1-week solo+Claude sprint targets ~10–20 points depending on story depth (many 1–2 pt wiring stories vs. one 8-pt centerpiece). Total: 61 stories · 202 points.
  • Story IDs: HT-xxx throughout this package; they become Jira keys when tickets are created (Jira sync is a separate, explicit step).

03 Phases at a glance

Phase 1 · Sprints 1–4

The Reliable Core

Habit CRUD, templates, 5 schedule types, actionable local notifications, streaks + forgiveness, dashboard, classification, quotes.
🚧 Gate: ≥40% of habit creators still checking in after 21 days
Phase 2 · Sprints 5–8

Intelligence

Questionnaire → user profile, AI plan generation, weekly coaching, personalized encouragement, medication reminders, guardrails + cost metering.
🚧 Gate: questionnaire-completers retain better than skippers; zero guardrail violations in logs
Phase 3 · Sprints 9–12

Senses

Voice creation & check-in (on-device STT), HealthKit / Health Connect auto-tracking, conversational assistant. Requires EAS dev-client builds.
🚧 Gate: auto-tracked habits retain better than manual; voice parse ≥95% accurate at confirm screen
Phase 4 · Sprints 13–15

Guidance & Polish

Vetted wellness suggestion library, Ramadan mode, prayer anchors, Arabic pass, web companion, accountability-partner spike.
🏁 Feature considered v1-complete
⛔ Phase discipline
Each phase must pass its gate before the next begins. If Phase 1 misses its retention gate, we fix Phase 1 or stop — we do not build AI on top of a tracker nobody uses.

06 Definition of Done

Per story

  • Acceptance criteria in 03-user-stories.html all pass.
  • Variable-scope check done on every touched component (no parent-scope variables used without props — the blank-page bug class).
  • npm run build passes and the screen renders on a real device / emulator with a clean console. Build passing ≠ runtime working.
  • Backend stories: unit tests for repository/queries logic; API tested via the envelope contract {data, error}.
  • Status updated on 04-status-board.html.

Per sprint

  • Max 4–5 files per commit for new components; verify build + render between batches.
  • Sprint verification checklist (in 02-sprint-plan.html) executed on device.
  • Jira tickets (once created) transitioned with platform tracking: Platforms: Web ✓ | iOS ✓ | Android ✓ — Done only when all targeted platforms work.
  • Sprint branch merged; status board updated.

Per phase

  • Phase gate metric measured and recorded on the status board.
  • E2E pass of the phase's flows on iOS (Expo Go / dev-client) and Android.
  • AI-touching phases: guardrail test suite (in ai-prompts.md) passes with zero violations.

07 Rollout & measurement

  • Rollout: habits_enabled per-user flag → Nadeem's account first, then PoC feedback group after Sprint 4.
  • Metrics logged from Sprint 1 (privacy-respecting, counts only): habits created, check-ins per day, notification permission grant rate, reminder→check-in conversion, D7/D21 habit retention, streak-freeze usage, AI suggestion accept/dismiss rate (Phase 2+), voice parse confirm-rate (Phase 3+).
  • AI cost meter from the first Anthropic call: tokens per user per week, alert threshold set in config.
✅ Standing safety rails (apply to every sprint)
Personal scope only (user_id, never person_id) · medication excluded from all AI code paths at the query layer · no medical advice in any generated string · health data evaluated on-device, raw samples never uploaded · AI proposes, user confirms.
