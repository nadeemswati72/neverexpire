📦 E1 — Habit Management

HT-101Habit data model & migrations P1·S15BE
As the system, I need habit, check-in and streak tables so every other story has a foundation.
  • habits, habit_checkins, habit_streak_state tables per research doc §15; user_id FK only, no person_id
  • All 5 schedule types representable in schedule_config JSON; category enum with 6 values
  • Unique constraint (habit_id, date, slot_index) on check-ins
  • init_db + seed script creates demo habits; user gains IANA timezone field
HT-102Habit CRUD API P1·S13BE
As a client app, I can create, read, update, archive and pause habits over REST.
  • GET/POST /api/v1/habits, GET/PATCH/DELETE /habits/:id — delete = archive, never hard-delete
  • JWT-scoped to the token's user; cross-user access returns 404
  • Validation errors return field-level messages in the {data,error} envelope
HT-103Check-in API with idempotency P1·S13BE
As a user, my check-ins are recorded exactly once, even when my phone retries after bad connectivity.
  • POST /habits/:id/checkins with date, slot, status (done/skipped/late), value, source
  • Duplicate (habit, date, slot) → 200 with existing record, not an error, not a second row
  • Status transitions validated (done can become skipped only via explicit undo)
HT-104Streak engine + StreakState cache P1·S15BE
As a user, my streak is computed fairly for my schedule — unscheduled days never break it.
  • Schedule-aware rules for all 5 types; freeze (2/month auto), repair (until noon next day, marked late), vacation pause
  • Check-in log is source of truth; StreakState recomputed on write
  • ≥15 unit tests: weekly quota edges, interval windows, timezone day boundaries, freeze exhaustion
HT-105Habits tab & list screen P1·S23MOB
As a user, I see all my habits grouped by category with today's state at a glance.
  • New tab (emoji nav icon) visible only when habits_enabled; route added to routes.js
  • List shows name, category emoji, schedule summary, today's check state, current streak
  • Empty state promotes the template gallery; 3-layer architecture respected
HT-106Create/edit habit screen P1·S25MOB
As a user, I can create a fully custom habit in under a minute.
  • Fields: name, category, schedule type + config, target (boolean/quantity+unit), reminder times, anchor
  • Each schedule type gets a tailored picker (weekday chips, quota stepper, interval + window, slots)
  • Edit pre-fills; schedule changes take effect from today, history untouched
HT-107Template gallery P1·S23MOB
As a new user, I add a good habit in one tap instead of designing one from scratch.
  • ~40 curated templates as static JSON, grouped by category, searchable
  • Tap → editor opens pre-filled with sensible schedule → save
  • Already-added templates are marked
HT-108Check-in interaction P1·S23MOB
As a user, marking a habit done feels satisfying — the emotional core of the loop.
  • Single tap toggles done; haptic + tick animation + visible streak increment
  • Quantity habits: quick +1 stepper with target progress
  • Undo within the same day; yesterday check-in offered until noon (repair, marked late)
HT-109Offline check-in queue P1·S25MOB
As a user, check-ins work with no signal and sync later without duplicates.
  • Queue persisted in AsyncStorage; UI reflects check-in instantly (optimistic)
  • Flush on foreground + connectivity regained; server idempotency absorbs retries
  • Airplane-mode E2E: offline check-in → reconnect → exactly one server record

⏰ E2 — Reminders & Notifications

HT-201Local notification scheduling engine P1·S38MOB
As a user, every reminder fires at the right time — offline, forever, without exceeding OS limits.
  • Rolling 48h scheduling window, re-planned on app open/foreground; pending count stays under iOS's 64 cap with 10+ interval habits
  • Anchors resolved at plan time: clock, relative ("+30m after wake"), prayer (local calculation)
  • Android 13+ notification permission requested in context on first reminder; denial → visible "reminders off" state, habits still work
  • Pausing/archiving a habit cancels its pending notifications
HT-202Actionable notifications (Done / Snooze) P1·S35MOB
As a user, I complete a habit from the notification itself, without opening the app.
  • Done and Snooze-30m actions on every habit reminder (notification categories)
  • Done records a check-in (source notification_action) with app foreground, background, or killed
  • Snooze reschedules once; a snoozed reminder never snoozes itself again automatically
HT-203Quiet hours & per-habit mute P1·S32MOB
As a user, the app never pings me at night, and I can silence one habit without deleting it.
  • Global quiet window (default 22:00–07:00), editable; correct across midnight
  • Per-habit reminder toggle independent of the habit itself
  • Medication category exempt by default (overridable) — enforced later by HT-802
HT-206Smart notification batching P4·S152MOB
As a user with several evening habits, I get one combined check-in ping, not three.
  • Habits due within the same 15-min slot merge into one "N habits due" notification
  • Tapping opens a multi-check-in screen; batching never includes medication reminders

🔥 E3 — Streaks & Forgiveness

HT-301Streak freeze P1·S41MOB+BE
As a user who missed one day, my streak survives — a freeze is consumed instead.
  • 2 freezes/month, auto-applied to the first misses; counter resets monthly
  • Freeze use is visible (frozen-day style in heatmap + "freeze used" note), never silent
  • Not applicable to medication items
HT-302Repair window P1·S41MOB+BE
As a user who forgot to log (not to do), I can check in yesterday's habit until noon today.
  • Yesterday's unchecked habits offer "did it late" until 12:00 local; recorded as late
  • Late counts for streak; stats distinguish late from on-time (honesty preserved)
  • After noon, the day is missed — no editing history beyond the window
HT-303Vacation mode P1·S41MOB+BE
As a traveling user, I pause everything for N days without losing my streaks.
  • Global pause with end date (or open-ended); paused days excluded from all streak/stat math
  • All reminders suspended except medication (which asks explicitly)
  • Return prompt on first open after the end date

HT-402Today strip P1·S42MOB

HT-403Streak hero P1·S41MOB
As a user, my best active streak greets me with a visual that grows.

HT-404Consistency heatmap P1·S42MOB

HT-405Category rings + period toggle P1·S42MOB
As a user, I see which life areas are thriving and which are struggling.

HT-406Rule-based insight card P1·S41MOB+BE

🤖 E7 — AI Planning & Coaching

HT-701AI plan generation endpoint P2·S68BE
As a user, the app drafts a realistic 3–5 habit starter plan from my profile.
  • POST /habits/ai/plan; Anthropic call server-side with tool-use JSON schema; prompt from ai-prompts.md §2
  • Code validation: 3–5 habits, valid categories (medication excluded), sane times, each with a one-line rationale
  • Invalid model output → one retry → graceful fallback to template suggestions; nothing auto-activates
  • Same endpoint shape accepts free-text goal parsing (voice-ready for S9)
HT-702Plan review UI P2·S65MOB
As a user, I stay in charge — the AI proposes, I dispose.
  • Draft cards with schedule, target, anchor + rationale; accept all / edit any / reject any
  • Accepted cards create habits via the normal CRUD path; rejected feedback stored for coaching signal
HT-703Weekly coaching job + suggestion cards P2·S85BE+MOB
As a user, I get at most one smart suggestion at a time — on the dashboard, never pushed.
  • Weekly batch over aggregates → one AiSuggestion (move-time / level-up / reduce-load) with rationale
  • Accept applies the change through CRUD; dismiss suppresses similar suggestions 2 weeks
  • Medication data provably absent from job input (query-layer filter test)
HT-704Personalized encouragement lines P2·S83BE
As a user, "Day 12 of reading — more than all last month" lands harder than any famous quote.
  • Stats-driven lines generated weekly (small model), cached; every claim backed by a real computed stat
  • Replaces generic quotes where data allows; same off-toggle; post-filter applies
HT-705Guardrail post-filters + audit log P2·S83BE
As the product owner, I can prove no AI output ever crossed into medical advice.
  • Post-filter per ai-prompts.md §6 on every AI response; violations rejected + logged, safe fallback shown
  • Audit table: prompt id, input hash, output, filter verdict, timestamp — for 100% of calls
  • Red-team suite (§7) automated in pytest; green required for phase close
HT-706AI cost metering P2·S62BE
As the product owner, I know AI spend per user before it surprises me.
  • Token counts logged per call; weekly per-user rollup; config alert threshold
  • Model routing: big model for plans/assistant, small for encouragement/insights
HT-707Conversational assistant P3·S128BE+MOB
As a user, I ask "why do I keep failing evening reading?" and get advice grounded in my own data.
  • Chat UI (text + voice via S9/S10 stack); context = user's stats aggregates + profile (prompt §5)
  • Scope limited to habit topics; medication excluded by query filter; every reply post-filtered
  • Red-team cases (dosage bait, diagnosis bait, jailbreak phrasing) pass with zero violations

💊 E8 — Medication Reminders

HT-801Category isolation & AI exclusion P2·S73BE
As the system, medication data can never reach an AI code path — by construction, not by prompt.
  • Query-layer filter excludes medication habits from every AI input builder; single shared function, unit tested
  • Medication fields: free-text label, times, optional free-text note — no drug DB, no structured dosage
  • No streaks/freezes/quotes/gamification apply to the category
HT-802Medication reminder reliability P2·S75MOB
As a user, my 8pm tablet reminder is the most reliable notification on my phone.
  • Ignores quiet hours by default (overridable); re-fires once after 15 min unacknowledged
  • Android SCHEDULE_EXACT_ALARM requested in context; exact delivery verified on Android 14
  • Delivery verified with app killed, both platforms
HT-803Adherence log & export P2·S73MOB+BE
As a user, I can show my doctor a clean taken/missed history — at my initiative.
  • Per-medication taken/missed/late list, filterable by date range
  • Export as plain-text/share-sheet list; no advice text anywhere in the export
HT-804Acknowledgment & missed-dose indicator P2·S72MOB
As a user, the app is honest about what it is: a reminder, never a medical adviser.
  • One-time acknowledgment on first medication habit ("reminds — never advises; follow your doctor")
  • Missed dose → neutral indicator ("Missed — see your notes"); never "take it now" or dosage guidance
