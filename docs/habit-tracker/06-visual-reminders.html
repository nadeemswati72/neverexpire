HT-201 Scheduling engine — how reminders stay under OS limits

iOS allows only 64 pending local notifications per app. The engine schedules a rolling 48-hour window and re-plans on every app open/foreground.

  • Plan: for each active habit, materialize occurrences for the next 48h from schedule + anchors (clock / "after Fajr" / "+30m wake") → schedule.
  • Re-plan: on app open, foreground, habit edit, or timezone change → cancel + regenerate the window. Idempotent.
  • Prioritize: if a pathological setup still exceeds the cap, medication wins first, then nearest-in-time habits; furthest-out habit reminders drop (they'll be re-planned before their time anyway).
  • Permission: Android 13+ asks in context — the moment the user sets their first reminder, with a one-line explanation. Denial leaves habits fully usable, marked "reminders off".
💡 Anchored times: anchors are resolved at plan time, so "after Fajr" naturally tracks shifting prayer times day by day — no special runtime logic, the 48h window recomputes it.
